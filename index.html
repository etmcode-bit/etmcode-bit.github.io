We formulate embodied tasks as SWE problems and explore how far Code-Only-as-Policy can go, analyzing its strengths and limitations. Benchmark results serve to validate the approach, not as the objective. We also view COAP as a complement to model-based methods, as it generates large-scale, controllable trajectories.

  • Data engine. Given offline time, coding agents iterate on a reusable code library. A working program then generates diverse trajectories efficiently and at scale for policy training.
  • Stable, fast execution. Decisions are explicit code, and no model is queried at run time, so execution is stable, fast and cheap. This suits industrial settings where the state can be measured reliably.
  • Generalization trade-off. Zero-shot generalization is difficult for code and generally calls for an agent in the loop. Code, however, is reusable: with offline development, it extends to new tasks and scenes.
